= Processing a message

`Message<T>.process()` runs a handler against a leased message and guarantees exactly one write-back, whatever the handler does.
This is how a message's lease should be ended, unless xref:manual-processing.adoc[manual processing] is genuinely called for.

[source,kotlin]
.Main.kt
----
val message = emails.receive()
message.process {
    sendEmail(message.payload) // <1>
    null // <2>
}
----
<1> If this throws, the message is requeued.
<2> The notes to record alongside a success: `null` for none.


== What happens to the message

* The handler returns → `successDelete`.
* The handler fails → `failureRequeue`, immediately — which itself defers to `failureDelete` when that failure was the last authorized attempt.
* A `timeout` longer than `processingTimeout` — or a handover slow enough to have already eaten into `processingGrace` — has its lease kept alive automatically, for exactly as long as the handler runs.
No parameter to configure, and nothing to misconfigure (see xref:internals:message-queue-algorithm.adoc#safeguard-keepalive[the algorithm document]).

A timeout, the caller's own cancellation, and a foreign `CancellationException` raised from inside the handler are told apart and handled correctly: see xref:internals:message-queue-algorithm.adoc#cancellation[].


== Parameters

[source,kotlin]
----
public suspend fun <T> Message<T>.process(
    timeout: Duration = this.expiresAt - Clock.System.now(),
    onFailure: (failure: MessageProcessingFailure) -> JsonElement = { JsonObject(it.defaultNotes()) },
    onRequeueFailure: (message: Message<T>, failure: MessageProcessingFailure, cause: Throwable) -> Unit = { _, _, _ -> },
    process: suspend (Message<T>) -> JsonElement?
)
----

[cols="1,1,3"]
|===
| Parameter | Default | Meaning

| `timeout`
| The lease's remaining time
| How long the handler may run before it is treated as a failed try.
Freely longer than the queue's own `processingTimeout`: the lease is then kept alive automatically for as long as the handler runs, up to `timeout`.
Throws `IllegalStateException` up front if the lease has already expired before the call even starts.

| `onFailure`
| Records the failure's default notes
| Produces the `notes` recorded alongside a timeout, a cancellation, or an exception — see `MessageProcessingFailure`.

| `onRequeueFailure`
| No-op
| Called if `failureRequeue`/`failureDelete` itself fails — a dropped connection, an exhausted pool — so that a database blip on one message's write-back can't propagate out and take the whole worker pool down with it.

| `process`
| _(required)_
| The handler itself.
Its return value is the `notes` recorded alongside a *success* — `null` for none.
|===

`MessageProcessingFailure` is one of `Exception`, `Timeout` or `Cancellation`, each with a `defaultNotes()` map describing it.
Return your own notes from `onFailure` to record something else:

[source,kotlin]
.Main.kt
----
message.process(
    timeout = 20.seconds,
    onFailure = { failure ->
        JsonObject(failure.defaultNotes() + ("attempt" to JsonPrimitive(message.notes.size + 1)))
    },
) {
    sendEmail(message.payload)
    null
}
----

TIP: To handle messages continuously, use the xref:worker-pool.adoc[worker pool] rather than looping over `process()` yourself.
